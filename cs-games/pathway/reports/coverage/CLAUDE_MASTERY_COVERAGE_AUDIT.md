## 2. How to read the findings

Two kinds of statement are mixed in the matrix and kept apart by the `confidence` column.

* **Measured or executed** (confidence high, or medium with a measured value): bank sizes counted from the real generators, skill attribution proven by running `resolveRecord`, the Worker's `cleanGameAttempt` and the shared evaluator on real generated questions. The generator fails if a recorded attribution fact no longer matches the code.
* **Judgment** (confidence low or medium without a measurement): whether a skill is objectively assessable, and which behaviours multiple-choice practice cannot show. These need educator confirmation. 107 rows are category B and **not yet verified**; their category says what blocks them, not that they have been replayed.

## 4. Findings by course

### Advanced CS (4 exceptions)

Variable Lab declaration assembly is attributed (registry: fully supported) but the registry has no measurement for it, and PR #46 left it teacher-assessed (B, low). Inheritance abstract, Inheritance override and Documentation builder have fully supported attribution (Mixed credit 420 of 420) and are limited by bank size: 5 families, 16 items and 12 items (C, high).

### AP CSP (49 exceptions, 1 now validated)

`csp-games/exam-readiness/mapping.js` already resolves many games to skills with `direct` quality, but PR #46 reviewed only seven CSP sources. The matrix probes the mapping for every CSP skill.

* **Roundoff vs. Overflow Lab, CSP-NUMERIC: implemented (section 5).**
* **Internet Layers Lab, six skills (DNS 7 families, IP 9, Protocols 11, Secure Networks 5, Systems 19, Packets 5) plus Resilience 6:** attribution is direct and correct, but the bank is `families x 5 surface profiles`. The profiles change only client, server, resource, domain and link names, so they are counted as one reasoning pattern. Every skill is below 30 (C).
* **Binary Builder:** capacity mode has 4 possible questions (bit lengths 4, 6, 8, 16); representation and pixels modes are single reasoning tasks with different numbers (C). Feedback appears only after Check, so first-attempt evidence is valid.
* **RGB Color Builder and ASCII Binary Builder (D):** the student sees a live swatch or live decoded character while editing, so the first Check can pass by trial and error without place-value reasoning. Read from the source, not browser-played, hence medium confidence. A format with no live feedback is needed.
* **Direct route, depth unmeasured (B, low):** Test Case Builder, Data Detective, Code Concepts, Trivial/Nontrivial, Binary Search Hunt, Simulation Lab, Algorithm Race, Parallel Processing Race, Cybersecurity Defender, AI Ethics, Copyright. Next wave should replay these the way section 5 does. AP CSP pseudocode semantics, not Java rules, must be used for Variables, Expressions, Procedures and Parameters.
* **Estimated-only routes (B, low):** vocabulary and Create Task Lab routes are capped by design. Whether term recognition is acceptable evidence is an educator decision.
* **E (5):** iterative development, collaboration, design for a user (project process), explaining data abstraction and procedural abstraction (written explanation). A dead branch was found: Response Builder abstraction items resolve to no skill.

### Workplace Readiness (94 exceptions)

* **Depth is not the problem.** Measured on the real hybrid generator: median 51 distinct reasoning signatures per concept, 83 of 94 concepts at 30 or more, 90 with all three difficulties, 4 below 20. (A static count of templates and kits suggested the opposite; the engine is the authority.)
* **Attribution is.** The Workplace page records a legacy class-report event (`activity: workplace-readiness-games`, skill/topic/subtopic dimensions). No scored `game-attempt` event with a concept is sent, and `questionEvidence` has no Workplace branch, so no answer credits any node.
* **A primary-concept rule is needed first.** 3,169 of 3,284 question units carry 2 or 3 concept tags and the family name rarely identifies one. Crediting every tag would credit several nodes for one answer. This needs a reviewed rule, which is a content decision for you and Work, so no adapter was built.
* **Knowledge, not performance.** Scenario items show whether a student knows the appropriate action. Eight concepts name a performed behaviour (presenting, nonverbal cues, self-representation, appearance, punctuality, diligence, dependability, working with minimal supervision) and are category E pending educator confirmation. 11 concepts have fewer than 30 signatures (C).

### Robotics (15 exceptions)

Parts Sprint has 4 to 14 distinct parts per category, 56 in total (C, high). Component Challenge has 25 choose, 18 fix, 12 tools and 20 solution scenarios, each its own family, behind adapter-pending selectors (C, medium). Course Architect (3) is open design work (E), taken from the PR #46 report and not re-verified. Identification and selection practice does not show physical engineering competence.

## 5. Implemented first wave: Roundoff vs. Overflow Lab to CSP-NUMERIC

**Why this lab:** 60 reasoning families (each with its own objective and kind), 360 questions, and an independent BigInt oracle already in its own tests.

**Defect found and repaired:** within the Integer topic, bit width alone predicted the answer for 112 of 120 questions (93%; width 4 to 7 meant Overflow, 8 and 10 meant Neither), because width and the error flag both derived from the variant index. The same coupling existed for decimal places and magnitude in the Precision topic. The generator now keeps the outcome on the original index and rotates width, decimal places and magnitude per family. After the repair the bit-width predictor equals the topic base rate (60%). The answer keys, wording of explanations, family and question counts are unchanged.

**Evidence and tier:** the lab is added to the reviewed CSP sources in `requirements/recommended.mjs`, so CSP-NUMERIC becomes Standard Practice (30 at 90%) for newly created classes. Existing classes keep their pinned snapshots. No tier above Standard is claimed: classification of a computed case is not Quick Recognition, and no difficulty or essential-topic requirement was configured.

**Known limits of this lab:** the topic itself narrows the answer (Integer never yields Roundoff; Precision never yields Overflow), which is real structure rather than a shortcut within a topic; Mixed mixes them. The lab has no difficulty levels and no reveal feature. The lab stores the answer label as the record topic and practice mode, which is not student-visible and does not affect attribution.

## 7. What is not claimed

* The 107 category B rows are not replayed; their attribution paths exist but depth, families and first-attempt behaviour are unverified.
* No Java code changed, so no JVM verification applied.
* The Chromium run used guest mode. The signed-in sync path (`recordGameAttempt` to the Worker) was reproduced field for field in the test but not run against an authenticated service.
* One browser engine only, no Safari, Firefox, Chromebook or screen reader.
* No educator has reviewed the Roundoff items, the E judgments or the performance list for Workplace.
* RGB and ASCII conclusions come from reading the source.

## 8. Recommended next waves, by value and risk

1. **Workplace adapter** (up to about 75 nodes plus 11 that also need depth): a reviewed primary-concept rule per question, a `game-attempt` event with a concept, and a Workplace branch in `questionEvidence`. Highest yield, needs a content decision first.
2. **Replay the direct-route CSP labs** (about 25 B rows): same method as section 5, one lab at a time, starting with Code Concepts (4 skills) and Test Case Builder (3 skills).
3. **Internet Layers expansion** (7 skills): add reasoning families, not profiles.
4. **Binary Builder expansion** (3 skills) and a **no-live-feedback format** for RGB and ASCII (2 skills).
5. **Parts Sprint formats** and a **Component Challenge adapter** (12 Robotics nodes).
