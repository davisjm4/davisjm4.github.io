## Outcome

Advanced CS practice now earns mastery-node evidence for every Java mode whose scoring is objective, whether a student practices that mode directly or meets it in Mixed Practice. The eleven modes that had no node now have one (nine new nodes, plus the existing `match-call` node accepting Order Arguments). Math Lab Mixed Practice now draws all seven scored modes. Boolean & Conditional records the difficulty it presents. One scoring defect in LinkedList was found and fixed. Three activities that cannot validly earn node evidence today (API Response Explorer, API Project Builder, Class Builder Rearrange) remain practice-only and are listed with reasons in a machine-readable registry. In a measurement of synthetic correct first-try answers through the real client-to-normalizer flow, each of the eleven modes went from 0 of 12 credited to 12 of 12, and every Mixed answer in every lab credits the node of the question shown (420 of 420 per lab).

## What was done, against the assignment

**Starting point.** The branch was created from the Phase 1 head. `main` was fetched and had not moved from `422398d`, so there were no conflicts to resolve. Before any change, the Phase 1 suites were re-run on the Phase 1 head: 17 runs, all exit 0 (`evidence/test-results-baseline.tsv`), and the graph regenerated byte for byte.

**The eleven unmapped modes.** Each engine, its metadata and its scoring were read, and scoring was re-derived independently of each engine's own answer key where a simple oracle exists (`java-mode-scoring.test.mjs`, eight tests). Decisions and reasoning are in `MISSING_MODE_DECISIONS.md`. In short: Order Arguments joins `match-call`; LinkedList `link` and `mutate` share one new `references` node; Inheritance hierarchy, override, tracer and debug, Documentation editor and builder, and Robot build and debug each get a node. No mode was left practice-only, and no node was created without objective scoring behind it.

**Math Lab Mixed Practice.** Mixed omitted Math Methods and Numeric Limits by design when they were added, not for a technical reason. `java-games/math-lab/mixed.js` rotates all seven modes in shuffled rounds, each question still comes from its own mode's generator, the difficulty control is shown in Mixed and applies to the two expansion modes, and credit and recorded difficulty follow the question shown. The tests that assumed the old rotation were updated, and the two READMEs that said Mixed uses only the original modes were corrected. Details are in `MIXED_PRACTICE_AUDIT.md`.

**Mixed Practice across labs.** Every lab with a Mixed mode was measured (420 questions each). No lab credits the wrong node. The verified low-risk corrections were made: Boolean now sends its difficulty, and Boolean, LinkedList, Inheritance, Documentation and Robot send the question's own mode and family through `java-games/lab-evidence.js`. Findings that would need a generator or graph-content change (ArrayList Mixed skew, no Search & Sort Mixed, small item banks, unbound family ids) are recorded as follow-up and were not changed.

**First-attempt evidence rules.** Unchanged and re-verified for the eleven modes: one scored attempt per question per node, wrong-then-right stays a miss, hints, reveals and skips never count as first-try correct, credit follows the actual question and never "Mixed", the difficulty recorded is the one presented, no duplicate credit, and daily session summaries are identical with the annotations in place.

**Graph compatibility.** Additive only; version unchanged; every id and the node order preserved; nine nodes and 95 families added; no policy attached; estimates provisional. Details, including snapshot and migration implications, are in `GRAPH_COMPATIBILITY.md`.

**Reusable validation and the gap registry.** `cs-games/pathway/tests/lib/lab-flow.mjs` drives any lab through generator, tracker, profile client, event, normalizer and node. `java-evidence-coverage.test.mjs` (15 tests) covers all 14 labs focused and Mixed, with negative tests for forged and misattributed events and for unknown modes. `evidence-gap-registry.json` has one entry per Java activity and mode (128 entries: 125 fully supported, 1 curriculum mapping needed, 1 intentionally practice-only, 1 unsupported) with the requested fields and the six requested statuses; `gap-registry.test.mjs` (9 tests) checks it regenerates identically, agrees with measured credit, and reports missing coverage instead of hiding it. `JAVA_MASTERY_COVERAGE_MATRIX.csv` has one row per game, mode and difficulty.

**Out of scope, untouched.** Teacher Tools UX, Google sign-in, Cloudflare Workers, D1 migrations, student profile enrollment, recovery credentials, class ownership, published class pathways, student sync authorization, the standards-based 0 to 4 scoring and teacher assessment generation were not modified. No graphical learning map, mastery certification or question-count threshold was implemented.

**Browser smoke test.** Chromium 153 through Playwright, with a synthetic profile and the API route blocked, driving the real pages from a local static server. Fifteen workflows: Math Lab Mixed on a 1280 by 800 desktop (56 questions, Intermediate) and on a 390 by 844 phone (21 questions, Advanced), Math Methods focused, LinkedList link, mutate and Mixed, Inheritance hierarchy, override, tracer and debug, Documentation editor and builder, Robot build and debug, and Boolean branch at Advanced. Every submitted event (an answer to a displayed question) was read back from the profile outbox and passed through the real server normalizer: all credited exactly the intended node with `n=1`, all seven Math modes appeared in Mixed, the recorded levels matched the selected ones, the phone layout had no horizontal scroll, and there were no page errors. The script answers with whatever control is visible, so this checks attribution, not correctness of answers; no other browsers, no real devices and no screen reader were tried. An earlier run showed intermittent page errors in Robot Algorithms; they reproduce identically on the Phase 1 pages and came from the script programmatically clicking controls a student cannot reach, so the script now touches only visible controls.

**Negative controls.** Nine controls (`evidence/negative-controls.log`) each re-introduce a Phase 1 behavior or a targeted fault into a copy of the tree and expect the Phase 2 tests to fail. All nine did and the unmodified copy passed.

**Before and after.** `EVIDENCE_CREDIT_BEFORE_AFTER.md`.

**Environment notes.** Node 22.23 and JDK 17 and 21 were used (CI uses Node 24). The shell is set to a UTF-8 locale because the Array Lab runtime check compares Java output containing the ↔ character; under this sandbox's default POSIX locale the JVM prints "?" and that check fails independent of this work. The Array Lab suite was not touched by Phase 2.

## Limits and honest notes

No human educational review was performed on any generated content: node titles and objectives, the registry's wording, or the question banks. Scoring validation shows that engines accept the intended answer and reject specific wrong ones; it does not show that questions are pedagogically well pitched. The registry's scoring evidence for modes outside the eleven is the existing lab suites, which pass, and was not independently re-derived in this package. The browser check ran against a local static server, not the live site, and Google sign-in, production data and the real Worker were not exercised. Evidence students submitted before this release is not re-attributed. Skips and revealed answers still emit no practice event, as before. Practice evidence is still not eligible for mastery policies, so nothing in this package can award mastery.

## Follow-up work

In rough priority order, each recorded in the registry or the reports: decide where API Response Explorer's skills belong and map it; write the host adapter for Class Builder Rearrange; expand the small Inheritance and Documentation item banks before relying on those nodes; rebalance ArrayList Mixed Practice; bind generator family ids for the labs that send unbound ones; consider a Mixed mode for Search & Sort; decide with the teacher whether Mixed Practice should default to something other than Beginner for the two Math expansion modes; and calibrate prerequisites and estimates for the new nodes. A deliberate graph version bump with a snapshot migration is the way to extend these changes to already-published class snapshots, and is not recommended unless a node or family is removed or renamed.
