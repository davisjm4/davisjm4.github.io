## Vocab

### Basics

<a id="algorithm"></a>

<details>
<summary>algorithm</summary>
<p><strong>Definition:</strong> A step-by-step process used to complete a task or solve a problem.</p>
<p><strong>Real-life example:</strong> A recipe for making grilled cheese is an algorithm because it gives you a set of steps to follow in order.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">// Algorithm for calculating a total
int price1 = 5;
int price2 = 7;
int total = price1 + price2;
System.out.println(total);
</code></pre>
</details>

<a id="computer-algorithm"></a>

<details>
<summary>computer algorithm</summary>
<p><strong>Definition:</strong> A set of instructions for a computer to follow to accomplish a specific task.</p>
<p><strong>Real-life example:</strong> A checkout system follows instructions to total prices, calculate tax, and display the amount owed.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">int total = 10 + 5;
System.out.println(total);
</code></pre>
<p>Many different algorithms can solve the same problem. Programmers often compare them for correctness and efficiency.</p>
</details>

<a id="pseudocode"></a>

<details>
<summary>pseudocode</summary>
<p><strong>Definition:</strong> A human-readable way to plan the steps of an algorithm without writing the exact syntax of a programming language.</p>
<p><strong>Real-life example:</strong> Writing the steps for calculating a grocery total before turning those steps into Java.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">// Pseudocode:
// Create total
// Add item prices
// Calculate tax
// Print total
</code></pre>
</details>

<a id="sequencing"></a>

<details>
<summary>sequencing</summary>
<p><strong>Definition:</strong> The order in which steps or instructions are completed.</p>
<p><strong>Real-life example:</strong> When making grilled cheese, you get the bread before adding butter and cheese. Changing the order can change the result.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">System.out.println(&quot;Get bread&quot;);
System.out.println(&quot;Add butter&quot;);
System.out.println(&quot;Add cheese&quot;);
System.out.println(&quot;Cook sandwich&quot;);
</code></pre>
<p>Java normally runs these statements from top to bottom in the order they are written.</p>
</details>

<a id="java"></a>

<details>
<summary>Java</summary>
<p><strong>Definition:</strong> A programming language used to build many kinds of applications. Java is object-oriented and is different from JavaScript.</p>
<p><strong>Real-life example:</strong> Java can be used for desktop software, enterprise systems, Android-related development, and games.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">public class Hello {
    public static void main(String[] args) {
        System.out.println(&quot;Hello Java!&quot;);
    }
}
</code></pre>
</details>

<a id="jdk"></a>

<details>
<summary>JDK (Java Development Kit)</summary>
<p><strong>Definition:</strong> The set of tools used to develop Java programs, including tools to compile and debug code.</p>
<p><strong>Real-life example:</strong> A mechanic needs tools to build and repair a car; a Java developer needs the JDK to build and debug Java programs.</p>
</details>

<a id="jre"></a>

<details>
<summary>JRE (Java Runtime Environment)</summary>
<p><strong>Definition:</strong> The environment needed to run Java programs. It includes the JVM and basic Java libraries but not the full development toolset.</p>
<p><strong>Real-life example:</strong> Someone playing a finished game needs the software required to run it, not necessarily all the tools used to build it.</p>
</details>

<a id="jvm"></a>

<details>
<summary>JVM (Java Virtual Machine)</summary>
<p><strong>Definition:</strong> The part of the Java runtime that executes Java programs.</p>
<p><strong>Real-life example:</strong> The JVM is like the machine that interprets the prepared Java program and runs it on the device.</p>
</details>

<a id="procedural-programming"></a>

<details>
<summary>procedural programming</summary>
<p><strong>Definition:</strong> A programming approach organized mainly around procedures or functions that operate on data in a top-down sequence.</p>
<p><strong>Real-life example:</strong> Following one long checklist from beginning to end is similar to a procedural program.</p>
</details>

<a id="object-oriented-programming"></a>

<details>
<summary>object-oriented programming (OOP)</summary>
<p><strong>Definition:</strong> A way of organizing programs around classes and objects so related data and behaviors can be grouped together.</p>
<p><strong>Real-life example:</strong> A phone contact keeps a person's name, phone number, picture, and other information together as one contact instead of scattering those values in unrelated places.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">public class Friend {
    public String name;
    public int age;
    public boolean hasDog;

public Friend(String friendName, int friendAge, boolean friendHasDog) {
    name = friendName;
    age = friendAge;
    hasDog = friendHasDog;
}

}
</code></pre>

<p>Object-oriented programming is useful when one real-world thing needs several related pieces of data and behaviors.</p>
</details>

<a id="camelcase"></a>

<details>
<summary>CamelCase</summary>
<p><strong>Definition:</strong> A naming style where multiple words are joined and each new word begins with a capital letter.</p>
<p><strong>Real-life example:</strong> A file named <code>TemperatureConverter.java</code> combines two words without spaces.</p>
<p><strong>Base structure / syntax:</strong></p>
<pre><code class="language-java">MyFirstProgram.java
</code></pre>
</details>

<a id="java-file"></a>

<details>
<summary>.java file</summary>
<p><strong>Definition:</strong> A source-code file used to store Java code. The filename should match the public class name.</p>
<p><strong>Real-life example:</strong> If the public class is named <code>Welcome</code>, the file should be named <code>Welcome.java</code>.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">public class Welcome {

}
</code></pre>

</details>

<a id="code-block-curly-braces"></a>

<details>
<summary>code block / curly braces</summary>
<p><strong>Definition:</strong> Curly braces <code>{ }</code> mark the beginning and end of a class, method, or other block of code.</p>
<p><strong>Real-life example:</strong> Braces are like the walls around a room: they show what belongs inside that space.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">public class Example {
    public static void main(String[] args) {
        // inside main
    }
}
</code></pre>
</details>

<a id="comment"></a>

<details>
<summary>comment</summary>
<p><strong>Definition:</strong> Text written inside code to explain it. Java ignores comments when running the program.</p>
<p><strong>Real-life example:</strong> A note in the margin of instructions helps the reader without changing the instructions.</p>
</details>

<a id="single-line-comment"></a>

<details>
<summary>single-line comment</summary>
<p><strong>Definition:</strong> A comment that begins with <code>//</code> and continues to the end of the line. Java ignores comments when running the program.</p>
<p><strong>Real-life example:</strong> A short note written in the margin of your work.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">// Create a Friend object
Friend jasmine = new Friend(&quot;Jasmine&quot;, 15, &quot;blue&quot;);
</code></pre>
</details>

<a id="multi-line-comment"></a>

<details>
<summary>multi-line comment</summary>
<p><strong>Definition:</strong> A comment that can span multiple lines. It begins with <code>/*</code> and ends with <code>*/</code>.</p>
<p><strong>Real-life example:</strong> A longer note attached to a section of instructions.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">/*
 * This section creates
 * the Friend objects.
 */
Friend jasmine = new Friend(&quot;Jasmine&quot;, 15, &quot;blue&quot;);
</code></pre>
</details>

<a id="javadoc-comment"></a>

<details>
<summary>Javadoc comment</summary>
<p><strong>Definition:</strong> A special documentation comment in Java used to describe classes, methods, fields, constructors, and other parts of a program.</p>
<p><strong>Real-life example:</strong> A label attached to a tool can explain what the tool is for and how it should be used.</p>
<p><strong>Base structure / syntax:</strong></p>
<pre><code class="language-java">/**
 * Documentation goes here.
 */
</code></pre>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">/**
 * Prints a greeting for this friend.
 */
public void greeting() {
    System.out.println(&quot;Good Morning!&quot;);
}
</code></pre>
<p>Java comment types include:</p>
<pre><code class="language-java">// Single-line comment

/*

Multi-line comment
*/

/**

Javadoc comment
*/
</code></pre>

</details>

<a id="internal-documentation"></a>

<details>
<summary>internal documentation</summary>
<p><strong>Definition:</strong> Comments written directly inside source code to help developers understand how or why the code works.</p>
<p><strong>Real-life example:</strong> Leaving a note for a teammate explaining why a calculation is done a certain way.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">// Calculate tax after all item prices are added.
double tax = total * 0.08;
</code></pre>
</details>

<a id="inline-comment"></a>

<details>
<summary>inline comment</summary>
<p><strong>Definition:</strong> A short comment placed on the same line as code.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">int score = 10; // starting score
</code></pre>
</details>

<a id="todo-comment"></a>

<details>
<summary>TODO comment</summary>
<p><strong>Definition:</strong> A comment that marks work that still needs to be completed or fixed.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">// TODO: Add input validation
</code></pre>
</details>

<a id="external-documentation"></a>

<details>
<summary>external documentation</summary>
<p><strong>Definition:</strong> Documentation stored outside the source code that explains the program to developers or users.</p>
<p><strong>Real-life example:</strong> A user manual or project website explains how to use software.</p>
</details>

<a id="readme"></a>

<details>
<summary>README</summary>
<p><strong>Definition:</strong> A common external documentation file that gives an overview of a project and often explains how to run or use it.</p>
<p><strong>Real-life example:</strong> A project README can tell a new teammate what the project does and how to get started.</p>
</details>

<a id="api-documentation"></a>

<details>
<summary>API documentation</summary>
<p><strong>Definition:</strong> Documentation that explains how other programmers can use classes, methods, or services provided by software.</p>
<p><strong>Real-life example:</strong> Java documentation explains what a method expects and what it returns.</p>
</details>

<a id="bug"></a>

<details>
<summary>bug</summary>
<p><strong>Definition:</strong> A problem in a program that causes an error or incorrect behavior.</p>
<p><strong>Real-life example:</strong> A bicycle that does not work correctly has a problem to troubleshoot; code can have problems that must be debugged.</p>
</details>

<a id="syntax-error"></a>

<details>
<summary>syntax error</summary>
<p><strong>Definition:</strong> An error caused by breaking Java's grammar or structure rules, such as missing punctuation.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">int x = 10 // missing semicolon
</code></pre>
</details>

<a id="runtime-error"></a>

### Classes

<a id="class"></a>

<details>
<summary>class</summary>
<p><strong>Definition:</strong> A blueprint used to describe what information and behaviors objects of that type can have. A class defines the structure, but it is not an actual object.</p>
<p><strong>Real-life example:</strong> A house blueprint describes how houses built from it should be structured, but the blueprint is not one of the houses.</p>

<pre><code class="language-java">public class ClassName {

}
</code></pre>

    public String name;

<p>Java class names should normally begin with a capital letter.</p>
</details>

<a id="object"></a>

<details>
<summary>object</summary>
<p><strong>Definition:</strong> A specific object created from a class. An object stores its own values for the instance fields defined by the class.</p>
<p><strong>Real-life example:</strong> If a class is a blank contact form, an object is one completed contact containing one person's information.</p>
<p><strong>Base structure / syntax:</strong></p>
<pre><code class="language-java">ClassName objectName = new ClassName(arguments);
</code></pre>
<p><strong>Java example:</strong></p>

</details>

<a id="property"></a>

<details>
<summary>property</summary>
<p><strong>Definition:</strong> Data that belongs to a class or object. In Java, this is commonly called a <strong>field</strong> or <strong>instance variable</strong>.</p>
<p><strong>Real-life example:</strong> A student can have properties such as a name, grade level, and student ID.</p>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">class Student {
    String name;
    int gradeLevel;
}
</code></pre>
<p><code>name</code> and <code>gradeLevel</code> are fields that store information about a <code>Student</code> object.</p>
</details>

<a id="constructor"></a>

<details>
<summary>constructor</summary>
<p><strong>Definition:</strong> A special part of a class that runs when a new object is created. It is commonly used to give the object's instance fields their starting values.</p>
<p><strong>Real-life example:</strong> When a new student enrolls, the school creates a record and fills in starting information such as the student's name and grade level.</p>
<p><strong>Base structure / syntax:</strong></p>
<pre><code class="language-java">public ClassName(parameters) {
    // setup code
}
</code></pre>

<pre><code class="language-java">public class Friend {

    age = friendAge;
}

}
</code></pre>

<p>A constructor:</p>
<ul>
<li>Has the <strong>same name as the class</strong>.</li>
<li>Has <strong>no return type</strong>, not even <code>void</code>.</li>
<li>Runs <strong>once</strong> when that particular object is created with <code>new</code>.</li>
</ul>
</details>

<a id="instance-field"></a>

<details>
<summary>instance field</summary>
<p><strong>Definition:</strong> A variable declared inside a class that stores one piece of information for each object created from that class.</p>
<p><strong>Real-life example:</strong> Every contact in a phone can have its own name and phone number. Those categories of information are like instance fields.</p>
<p><strong>Base structure / syntax:</strong></p>
<pre><code class="language-java">accessModifier dataType fieldName;
</code></pre>
<p><strong>Java example:</strong></p>
<pre><code class="language-java">public class Friend {
    public String name;
    public int age;
    public String favoriteColor;
}
</code></pre>
<p><code>name</code>, <code>age</code>, and <code>favoriteColor</code> are instance fields.</p>
<p>Each object can store different values in those same fields.</p>
</details>

<details>
<summary>instance</summary>

<p><strong>Java example:</strong></p>
<pre><code class="language-java">Friend jasmine = new Friend(&quot;Jasmine&quot;, 15, &quot;blue&quot;);

<p><code>jasmine</code> and <code>tyler</code> are two different instances of the <code>Friend</code> class.</p>

</details>

<details>
<summary>attribute</summary>

<p><strong>Real-life example:</strong> A friend can have attributes such as a name, age, favorite color, or whether they have a dog.</p>
<p><strong>Java connection:</strong> Attributes are stored in <strong>instance fields</strong>.</p>

    public int age;
    public boolean hasDog;

        int number = 246;
        System.out.println(number % 2); // 0 means it is even

        int threeDigitNumber = 245;
        System.out.println(threeDigitNumber % 100); // 45
    }
}

<a id="code-parameters-and-arguments"></a>

Parameters and Arguments

public class ParameterExample {

    static void dog(String color, int age) {
        System.out.println(color + " fur and " + age + " years old.");
    }

    public static void main(String[] args) {
        dog("brown", 5);
        dog("black", 7);
        dog("white", 2);

In the method declaration, color and age are parameters.

In dog("brown", 5);, "brown" and 5 are arguments.

<a id="code-method-overloading"></a>

Method Overloading

public class OverloadingExample {

    static void dog(String color) {
        System.out.println("The dog has " + color + " fur.");
    }

        System.out.println("The dog is " + age + " years old.");
    }

    static void dog(String color, int age) {

        dog("brown");
        dog(5);
        dog("black", 3);

<a id="code-void-vs-returning-a-value"></a>

Void vs. Returning a Value

A void method performs an action but does not return a value:

static void printMessage() {
    System.out.println("Hello");
}

A non-void method returns a value:

static int getNumber() {
    return 13;
}

The returned value can be stored and reused:

int number = getNumber();
System.out.println(number);

<a id="code-returning-a-variable"></a>

Returning a Variable

public class ReturnExample {

    static int raddish() {
        int pumpkins = 25;
        return pumpkins;
    }

    public static void main(String[] args) {
        int veggie = raddish();
        System.out.println(veggie);
    }
}

The return type and the returned value must be compatible.

<a id="markdown-style-guide-for-coding-notebooks"></a>

Markdown Style Guide for Coding Notebooks

Follow this guide to keep your coding notebook clear, consistent, and professional.

This ensures your notes are easy for you and others to read later.

Headings

When to use: Organize your notebook into sections such as days, topics, or projects.

# for the notebook title. Use this once at the top.

## for each major topic.

### for subsections such as Notes, Practice, or Reflections.

Example

# My Coding Notebook

## Day 1

### Notes

### Practice

Text Formatting

When to use: Highlight important ideas or add emphasis.

Use bold for key terms or definitions.

Use italics for emphasis or side comments.

Use inline code for Java keywords, method names, variables, or commands.

Example

**Class** = a blueprint for objects

*Remember:* always test your code.

Use `System.out.println()` to print.

Code Blocks

When to use: Anytime you write multiple lines of code.

Use inline code for short snippets and fenced code blocks with the language name for full examples.

Example

```java
public class Hello {
    public static void main(String[] args) {
        System.out.println("Hello World!");
    }
}
```

Lists

When to use: Organize steps, notes, or key ideas.

Use numbered lists for sequences or steps.

Example

1. Define the class.
2. Write the `main` method.
3. Test your program.

Use bulleted lists for items that do not need to be in a specific order.

Example

- Variables
- Loops
- Conditionals

Checklists

When to use: Track progress on assignments or tasks.

Example

- [x] Complete coding warm-up
- [ ] Finish project draft
- [ ] Reflect on learning

Blockquotes

When to use: Call out notes, reminders, reflections, or teacher comments.

Example

> 💡 Remember: Test your program after making a change.

Tables

When to use: Compare values, track progress, or organize data neatly.

Example

| Task | Status | Notes |
|---|---|---|
| Homework 1 | Done | Submitted |
| Homework 2 | Pending | Needs review |

Links & Images

When to use: Add references, resources, or visuals.

Link Example

[Java Documentation](https://docs.oracle.com/en/java/)

Image Example

![Markdown Logo](https://upload.wikimedia.org/wikipedia/commons/4/48/Markdown-mark.svg)

Make an Image a Link

Place the image between opening and closing link tags.

<a href="website address">

![Image description](image-address)

</a>

Collapsible Sections

When to use: Hide solutions, extended notes, vocabulary definitions, or extra details.

Example

<details>
<summary>Click to reveal solution</summary>

```java
System.out.println("Answer: 42");
```

</details>

Footnotes

When to use: Add references or side notes without cluttering the page.

Example

This concept is related to object-oriented programming.[^1]

[^1]: See "Objects and Classes" in your textbook.

Style Rules

Consistency Matters More Than Creativity

Always use headings to structure your notes.

Always use code blocks for multi-line code.

Keep similar sections formatted the same way.

Clarity First

Bold key terms.

Use lists instead of long sentences when outlining steps.

Use Java syntax highlighting for Java code.

Professional Tone

Keep school and project notes clear and readable.

Use blockquotes for reflections, reminders, or teacher feedback.

Track Your Learning

Use checklists to mark what is complete.

Use collapsible sections when you want to hide details until you need them.

Bottom Line

Headings = Structure

Bold/Italic = Emphasis

Code blocks = Code

Lists = Steps and ideas

Tables = Organization

Checklists = Progress

Blockquotes = Notes and tips

Collapsible sections = Hide/show detail

Keep it simple, consistent, and clear.
