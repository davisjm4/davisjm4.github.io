## 4. Public API (browser `WRG.*`, Node `require`)

```js
const h = WRG.selector.createHybrid(lib, WRG.composeContent);  // ~100 ms, once per page load
WRG.selector.eligibleUnits(h, filters)       // authored + composed units matching filters
WRG.selector.capacity(h, filters)            // { units, signatures, authoredPatterns, composedConfigurations, families }
const s = WRG.selector.createSession(h, { seed, filters });  // same API as WRG.generator.createSession
s.next()                                      // challenge (standard instance contract + c.cx, c.source)
WRG.selector.renderUnit(h, unit, { seed, contextId, avoidBestIndex })
WRG.selector.validate(h, challenge)           // null if valid, else error list
```

`filters` has exactly the existing shape: `{ skills, category, modes, difficulty, context }`. The generator, grader, feedback, validator and UI modules are **not modified**; composed challenges pass the existing `validateChallenge` and grade with the existing `grader.js`.

## 5. Modes, filters, Session Summary

- Modes: unchanged ids (`decision`, `nextstep`, `order`, `find`). Composed challenges set `mode` like authored ones; no registration step.
- Filters: every filter is honoured (bulk-tested for all modes, difficulties, the 66 skill/difficulty cells and all 13 settings). The home-screen note now counts **distinct reasoning problems** (authored patterns + composed configurations) and keeps the existing warning below 20.
- Session Summary / tracker: unchanged. `tracker.record` receives the same `{ skill, category, mode, difficulty }`. Stored data keys are unchanged (privacy test still passes).
- Resume: the stream is deterministic from seed and filters, so reload/Continue resumes the same challenge (browser-tested). Students mid-session when this is deployed will get a **different** stream after the update, because the generator changed. Stats are kept; the next challenge comes from the new stream.

## 6. Build, test, cache

```bash
cd wpr-games/workplace-readiness
npm ci
npm run build            # writes content-bundle.js (unchanged) and compose-bundle.js
npm test                 # build + validate + 129 unit + 102 compositional + 36 browser tests
npm run docs:compose     # optional: re-run the audit and regenerate DIVERSITY_REPORT.md
```

Expected: unit 129/129, compositional 102/102, browser 34/36. **The two browser failures are pre-existing on b900c9f** and unrelated to this package: `filters: an impossible combination…` (it expects Mathematics + Advanced to be empty, but commit 8464f54 added Advanced Mathematics) and `accessibility: axe…` (rule `region`: the "← WPR Games" link sits outside a landmark). They fail identically without this package.

Cache-busting: `?v=wr-cx-20261022-1` on the three compose scripts, `?v=wr-cx-content-20261022-1` on `compose-bundle.js`, `?v=wr-20261022-cx1` on `app.js`. **Bump the compose-bundle version whenever `content/compose` changes and the bundle is rebuilt.** Never hand-edit either bundle.

## 7. Post-deploy smoke test

1. Open `/wpr-games/workplace-readiness/`, DevTools console: no errors; `WRG.app.hybrid.catalog.units.length` > 3000.
2. Home note for "All 22 skills": about 1,871 distinct reasoning problems. Integrity + Advanced: 20 or more.
3. Play five challenges in each mode; check feedback appears and Session Summary counts them.
4. Reload during practice: the same unanswered challenge returns.
