### What the generation sweep covered

5370 generated challenges across all three modes and difficulties. Each one was validated before display (source passage, writing question, two distinct evidence statements, matched explanations, no placeholders, one gap and four options for Missing Piece, an unsolved start for Rearrange), graded with its correct answer, and graded again with every wrong answer. Rearrange additionally accepts both evidence-pair orders; a separate exhaustive test grades all 5,040 orderings of each of the 30 writing models against an independent oracle and requires exactly two accepted orders.

| Verified property | How |
|---|---|
| Deterministic generation | Same seed gives identical challenge JSON for every model and mode; same seed gives identical sequences |
| Correct source-to-response relationships | Each evidence sentence keeps its source-fact reference; the fact is present in the excerpt; each explanation links to its evidence |
| Valid RACECES roles | Every sentence has one role; pair ids and tags are consistent |
| Correct grading and incorrect-answer rejection | 16257 wrong answers rejected with feedback |
| Accepted alternative evidence-pair orders | Both pair orders graded correct in every Rearrange challenge |
| No missing required pieces | Seven sentences, exactly one gap, four options, one best answer |
| No contradictory or unsupported content | Numbers must appear in the source; evidence must overlap its source fact; excluded-vocabulary scan |
| Feedback quality | Rearrange mistakes name the information involved and never say "sentence 4 belongs in position 6" |
| Session tracking | Totals, per-mode and per-role accuracy, error categories, persistence, reset, corrupt storage, 6,000-record long session |
| Repetition control | 900-challenge Mixed Practice run: no model within two challenges, no signature within 30 |
| Static safety | No unseeded random calls, no eval, no network calls, no external URLs or resources in any shipped script or page |

## What was NOT tested

- Browsers other than Chromium (Safari, Firefox, Edge). Safari/iOS in particular has its own pointer-event and sticky-positioning behavior.
- Physical Chromebooks and physical phones or tablets. "Chromebook" and "mobile" results come from emulated viewports in desktop Chromium on Linux.
- Touch dragging of sentences. Drag-and-drop was exercised with mouse-driven pointer events; touch devices were exercised with tap-to-move, which is the intended touch path. A real finger drag has not been run.
- Screen readers (NVDA, JAWS, VoiceOver, TalkBack). Accessibility checks cover roles, names, live-region text, focus movement, keyboard operation, and contrast ratios, but no assistive technology was run.
- Slow devices and low memory; performance was not profiled.
- Review by an educator or writing specialist. All content and distractor judgments are the author's.
- Deployment on GitHub Pages under /raceces-games/. The site was served from a local test server at the site root; all paths are relative, but the live subpath has not been loaded.

## How to re-run

```
npm install            # installs Playwright (dev only)
npx playwright install chromium
npm test               # build, validate, Node tests, browser tests, regenerate docs
npm run sweep          # generation sweep only
```

The browser harness (`tests/browser/harness.js`) finds Playwright on the normal module path or in `PLAYWRIGHT_MODULE`, and uses `/opt/pw-browsers` if `PLAYWRIGHT_BROWSERS_PATH` is unset.
