# Content and generator schema

_The example JSON below is produced by running the real generator with seed `doc`. Regenerated by `tools/gen-docs.js`._

## Source of truth

Content lives in `content/topics/*.json`. `npm run build` flattens it into `js/data/content-bundle.js` (never edit the bundle). `npm run validate` checks it.

## Topic

```json
{
  "id": "solar-panels",
  "subject": "Energy and technology",
  "title": "Solar panels",
  "intro": "Solar panels are flat devices made of many small cells that capture energy from sunlight.",
  "facts": [
    {
      "id": "f1",
      "text": "Each cell in a solar panel is made of a material that produces an electric current when light strikes it.",
      "ev": "A solar cell produces an electric current whenever light strikes its surface.",
      "tag": "how cells react to light"
    },
    {
      "id": "f2",
      "text": "Panels have no moving parts, so they make electricity quietly and need little repair.",
      "ev": "Panels have no moving parts, so they work quietly and need little repair.",
      "tag": "having no moving parts"
    },
    "…"
  ],
  "models": [
    "(see below)"
  ]
}
```

| Field | Meaning |
|---|---|
| id, subject, title | Stable identifier, subject area, display title |
| intro | One-sentence orientation that opens every excerpt |
| facts[].id | Stable fact id, unique within the topic |
| facts[].text | Self-contained sentence placed in the excerpt (must not depend on neighboring sentences) |
| facts[].ev | The evidence sentence a student reads in a response; must stay grounded in `text` (70% content-word overlap, same numbers) |
| facts[].tag | Short noun phrase naming the fact; used in prompts ("the information about rooftop installation") and feedback so no C1/C2 labels are shown |

## Writing model

```json
{
  "id": "solar-panels-m1",
  "family": "function",
  "level": "beginner",
  "q": "What makes solar panels a practical way to make electricity?",
  "restate": "Solar panels are a practical way to make electricity because of how they work and where they can go.",
  "answer": "Solar panels are practical because they turn light directly into electricity and fit onto spaces that already exist.",
  "ev": [
    "f1",
    "f3"
  ],
  "exp": [
    "That means sunlight itself becomes the source of power, with no extra step such as burning something.",
    "Using a roof lets a building produce power without needing a new piece of land."
  ],
  "rep": [
    "Light that strikes a cell causes it to produce an electric current.",
    "Panels are placed on rooftops that would otherwise be empty."
  ],
  "sum": "Altogether, panels are practical because they change light into electricity and can sit on spaces buildings already have.",
  "sumNew": "Altogether, panels are practical because they change light into electricity, and engineers rate each one in watts.",
  "bad": "Solar panels are practical because they store enough energy to power a building for a year without sunlight.",
  "badRestate": "Panels come in many sizes and are rated by how much power they can produce.",
  "off": "f7",
  "offExp": "Because output is measured in watts, buyers can compare how much power different panels produce.",
  "topicId": "solar-panels"
}
```

| Field | Role in the response / use |
|---|---|
| id, family, level | Stable id; reasoning family; beginner / intermediate / advanced |
| q | The writing question |
| restate (R) | The question turned into a statement, with no claim |
| answer (A) | The claim that answers the question |
| ev[0], ev[1] | Fact ids supplying evidence sentences C1 and C2 |
| exp[0], exp[1] | Explanations E1 and E2; each says why its own evidence supports the answer |
| sum (S) | Summary reinforcing the claim with no new information |
| rep[0], rep[1] | Distractors: repeat the evidence without explaining it (for E gaps) |
| sumNew | Distractor: summary that adds a new fact |
| bad | Distractor: unsupported claim |
| badRestate | Distractor: restatement of a different focus |
| off | Fact id in the excerpt that does NOT support the claim |
| offExp | Distractor: explains the off-topic fact |
| dependency (optional, unused) | Reserved for a genuine logical dependency that forces one evidence pair first. None of the current models has one, so both pair orders are always accepted |

## Response model (built by `js/engine/model.js`)

Every sentence carries `uid` (`<model>#<slot>`), slot (R, A, C1, E1, C2, E2, S), role (R, A, C, E, S), pair, text, `factId` and `source` for evidence, `explains` for explanations, and `tag`. Students see only the letters R, A, C, E, S.

## Challenge objects

### Identify the Parts

```json
{
  "id": "identify:solar-panels-m1:E:1:doc",
  "mode": "identify",
  "level": "beginner",
  "family": "function",
  "prompt": "Select the explanation connected to the source's information about how cells react to light.",
  "multi": false,
  "targetKey": "E:1",
  "solution": {
    "ids": [
      "E1"
    ]
  },
  "sentences": [
    {
      "id": "R",
      "text": "Solar panels are a practical way to make electricity because of how they work and where they can go."
    },
    {
      "id": "A",
      "text": "Solar panels are practical because they turn light directly into electricity and fit onto spaces that already exist."
    },
    {
      "id": "C2",
      "text": "Panels can be bolted onto rooftops, using space that is otherwise empty."
    },
    "…"
  ],
  "signature": "identify|solar-panels-m1|E:1"
}
```

Targets: `R`, `A`, `S`, `C:1`, `C:2`, `E:1`, `E:2` (single selection; the pair is named by topic tag), `C*`, `E*` (select every matching sentence; both instances accepted).

### Rearrange the Response

```json
{
  "id": "rearrange:solar-panels-m1:-:doc",
  "mode": "rearrange",
  "items": [
    "A",
    "C1",
    "R",
    "C2",
    "E1",
    "S",
    "E2"
  ],
  "solution": {
    "order": [
      "R",
      "A",
      "C1",
      "E1",
      "C2",
      "E2",
      "S"
    ],
    "alternate": [
      "R",
      "A",
      "C2",
      "E2",
      "C1",
      "E1",
      "S"
    ]
  },
  "signature": "rearrange|solar-panels-m1"
}
```

Grading is semantic (`js/engine/rearrange.js` → `analyze`): Restate first; Answer second; Summary last; positions 3–4 and 5–6 are each a Cite Evidence followed by its own Explain Evidence. Pair order is free.

### Choose the Missing Piece

```json
{
  "id": "missing:solar-panels-m1:E1:doc",
  "mode": "missing",
  "missingSlot": "E1",
  "missingRole": "E",
  "prompt": "One sentence is missing. It needs to do the job of Explain Evidence. Which sentence fits best?",
  "shown": [
    {
      "id": "R"
    },
    {
      "id": "A"
    },
    {
      "id": "C1"
    },
    {
      "id": "E1",
      "gap": true
    },
    {
      "id": "C2"
    },
    {
      "id": "E2"
    },
    {
      "id": "S"
    }
  ],
  "options": [
    {
      "id": "o1",
      "kind": "correct",
      "plays": "E"
    },
    {
      "id": "o2",
      "kind": "unsupported",
      "plays": "A"
    },
    {
      "id": "o3",
      "kind": "repeat",
      "plays": "C"
    },
    {
      "id": "o4",
      "kind": "summaryLike",
      "plays": "S"
    }
  ],
  "correctId": "o1",
  "signature": "missing|solar-panels-m1|E1"
}
```

| Option `kind` | Used as a distractor for | Feedback message explains |
|---|---|---|
| repeat | Explain Evidence | Repeating evidence is not explaining it |
| offExp | Explain Evidence, Cite Evidence, Summarize | Explains a different detail |
| offFact | Cite Evidence and others | A real detail that does not support this answer |
| unsupported | Every role | The source does not support the claim |
| summaryLike | Every role | A summary adds new information, or belongs at the end |
| wrongFocus | Restate, Answer | A restatement of a different focus |

## Generator behavior

- `Generator.build(index, {mode, modelId, targetKey, seed})` is pure and deterministic; every test and the game use it.
- `Generator.next({mode, level})` chooses mode (Mixed Practice picks the least-used recent mode), level (All picks the least-used recent level), then a writing model: models used in the last 8 challenges are excluded, then penalized for repeating the recent family (3 challenges) or topic (2), then least-used wins. Rearrange also avoids models seen in that mode in the last 30. The target role or slot is the least recently used, never repeating a recent signature.
- History is bounded to 60 entries and restored from session storage.
- Excerpt composition: intro + the two evidence facts + the off-topic fact + filler facts (5, 7, or 8 facts total by level), in a seeded order.
- Seeds: the browser seeds from the session start time (override with `?seed=abc` for reproducible play); tests use fixed seeds.
