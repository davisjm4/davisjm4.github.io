# Acceptance scenarios

**Specification for future validation.** These tests describe required outcomes and proposed checks. A baseline observation is historical evidence. Record new runs by requirement, commit, environment, device, outcome and evidence. Use the [isolated full-role environment](https://github.com/davisjm4/davisjm4.github.io/tree/audit/full-role-ux-environment) or an equivalent isolated fixture. No real class records are needed.

## Teacher-directed learning

Fixture: two authorized teachers with distinct classes, one class of at least 24 synthetic profiles, a student with saved map selection and partially answered practice, one class-wide assignment for skill/area B, one individual assignment for A, a separate selected-group item and unrelated destination C. Use both activation orders. Exercise focused skill, area, group and supported activity targets. Compare desktop, tablet and phone, and use keyboard-only switching and release.

| Test ID | Setup and steps | Required outcome |
| --- | --- | --- |
| CSG-AT-TDL-01 | Publish A for the student, then B to the class. Repeat with the reverse creation order. Return to My Class. Add a same-target pair. | Today's Classwork lists B first. Your Catch-Up Work lists A below. Start either in either order. A same-target pair yields one recommendation with source labels and inspectable assignment statuses. |
| CSG-AT-TDL-02 | Start A, enter an answer without submitting, then activate B. Observe notice, complete or explicitly pause A, switch to B and back. | A new assignment never steals focus, navigates away, or discards the answer. Resume restores each supported state. Both assignments stay available. |
| CSG-AT-TDL-03 | Save an independent position, complete assigned work, test Resume Previous Path and Continue From Here. Repeat while a restriction makes the old position unavailable. | Each offered action lands at its intended location. Preserve old position during a restriction and make it available again after release. Completing the assignment does not implicitly release manual restrictions. |
| CSG-AT-TDL-04 | Test individual restriction with advisory classwork, class restriction with advisory individual work, both restricted, and no restriction. Try launching via Map, List, search, direct class URL, return link and cached state. Try the same class activity after a permission change. | A and B remain available under overlap. C is restricted only when an applicable active grant requires it. With no restriction C follows ordinary access. Cross-class targets are denied independently of grant union. |
| CSG-AT-TDL-05 | With two active grants, release one. End its assignment. Release the last grant. Repeat bulk release with a stale or failed row and retry. | Other grant stays active, and teacher sees which grant remains. End removes only its associated grant and active work. Released but still active work stays available. Last release restores exploration. Results and actor history are explicit and retries do not duplicate records. |
| CSG-AT-TDL-06 | Compare identical first independent, assisted, retry and unsupported attempts via A, B and ordinary class practice. Replay a sync and share one target between assignments. | Same supported outcomes, evidence eligibility and formative results through the existing evaluator. Unsupported work stays practice-only. Replays, assignment links and status updates produce no extra evidence. |
| CSG-AT-TDL-07 | Preseed qualifying evidence and teacher 4/4. Issue, edit, switch, complete, restrict, release, end and reassign. Then use the existing authorized review flow to revise a score. | Assignment actions preserve original first attempts, level inputs and official result. Only the independent assessment flow changes the official outcome and records provenance. |
| CSG-AT-TDL-08 | In 24-student class restrict individuals and an overlapping group/class. Reopen dashboard, sort and filter, release one and bulk-release. Try mutations with another teacher, student, and stale credentials. | Active Restrictions appears first with unique count, IDs, targets, sources and effective restriction. Restricted students lead the default roster. Release works without searching the full roster. Unauthorized actions fail without disclosure. |
| CSG-AT-TDL-09 | Schedule B in class time zone, observe before and after activation. Cancel a second pending item. Compare one student, selected group and class. Test retry and expired or removed membership. | The right recipients receive the supported targets at the right time. Scheduled/canceled items have no active effect before start. A newly enrolled student receives active whole-class work but never joins a selected group automatically. A selected recipient who loses enrollment cannot launch class work. The selected set and prior completion history are preserved. Audit actor and states persist. |
| CSG-AT-TDL-10 | Go offline with stale or unknown permission and unsent input. Try a new class launch, reconnect after access changes, and replay from the original class context. Open the same activity via its public URL and try to submit guest attempts as class work. | Explain pending permission and preserve input. Defer the new class launch until verified. Recheck class authorization and accept only eligible queued class writes. Public guest play remains available independently. Its attempts leave class evidence counts, assignment status and official scores untouched, including after sign-in from the same browser. |
| CSG-AT-TDL-11 | Complete a mapped qualifying task, attempt it again, and use one target for two assignments. Try an unsupported task and complete it through authorized teacher confirmation. | Observable task evidence completes work only under the published criterion. Unsupported work requires teacher confirmation, which records status and actor only. One attempt remains one proficiency record. |
| CSG-AT-TDL-12 | Finish restricted work using default manual release. Attempt unrelated class practice, then explicitly release the student's grant from a whole-class restriction. If automated release is offered, run the case again with an intentionally configured condition. | Default completion leaves restriction in force. A one-student release leaves other students and grants unaffected. An automated release applies only to its configured grant and condition. |

Verify no evidence vs incorrect and confirmation at the control. |
| CSG-AT-05 | CSG-TCH-04, CSG-MAS-03 | For a self-paced class with calendar exceptions, change a skill target. | CSG-AT-06 | CSG-TCH-05, CSG-SES-02, CSG-SEC-02 | Create, assign and submit a frozen diagnostic in class-linked and anonymous modes; verify retakes, feedback timing, reports, suppression, export and targeted remediation. Check QTI reachability and label external import verification separately. |
| CSG-AT-07 | CSG-SES-01/02, CSG-STU-01, CSG-SEC-02 | Guest uses My Session and legacy summary route after practice, prints named PDF, copies or exports supported details, reloads, rolls over the local day and resets. No duplicate credit, unintended history reset or identity sync. |
| CSG-AT-08 | CSG-UX-01/02/03 | Exercise affected role at 390, 768, 1024, 1366 and 320 CSS px; use zoom, keyboard, reduced motion, touch and screen reader. Verify feedback, modal/panel dismiss, focus return, visible restrictions, and equivalent list access. |
| CSG-AT-09 | CSG-SEC-01/03, CSG-TDL-04 | Change class, recipient and target IDs, replay writes, revoke sessions, attempt production test credential use, and verify owner-scoped audit history. Server rejects forged context without disclosing unrelated records. |
| CSG-AT-10 | CSG-TRK-01, CSG-DEV-01/02 | Confirm IDs and links, baseline approval and release records. Validate tracker preserves prior IDs and history, with independent design, implementation and verification states. |
| CSG-AT-11 | CSG-MAS-02/03, CSG-STU-03, CSG-TCH-02/04 | On fixed eligible attempts, tighten and loosen class defaults, area rules and skill overrides, including minimum correct. For the same course rubric, the formative level and progression remain stable. Target status may change. Verify both teacher and student see three distinct results with provenance and an unchanged official score. Repeat with no evidence, unsupported evidence and a practice-only skill. |
| CSG-AT-12 | CSG-MAS-01/03/04, CSG-SEC-02 | Replay identical events across old and new readers, refresh and restart a target window, then add a qualifying first attempt and replay it. Class windows and caches must never filter course evidence or overwrite historical results. New evidence updates only the results for which it is eligible, once. Exercise guest parity, first-attempt dedupe, Level 3 progression, optional Level 4 and extension/recommendation behavior. |
| CSG-AT-13 | CSG-MAS-03, CSG-DEV-01 | Replay the same scoped evidence through the legacy and independent evaluators. Include legacy results above, below and equal to the current result, earlier policy snapshots, unsupported records and missing provenance. Both teacher and student views explain each mismatch, label original policy context, display the independently computed current level, and preserve historically earned progression even where the current level is lower. Verify original evidence and teacher-verified scores are byte-for-byte or field-for-field unchanged, preserve policy-bound awards, and label unavailable history. Rehearse rollback and verify compatible readers, exports, cache refresh and concurrent publish. Record replay and regression results before any evaluator deployment. |
| CSG-AT-14 | CSG-DEV-03, CSG-PRD-02, CSG-CUR-01/02, CSG-UX-01 | Review a new activity and a synthetic fifth pathway from guest and class entry through launch, evidence, return and reports. Record the shared components used. A duplicate interface blocks release without an approved exception and tested accessible fallback. A declared unsupported capability stays explicit and earns no unsupported evidence. |
