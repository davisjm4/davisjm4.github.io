# Teacher-directed learning

**Approved product contract · planned.** This contract records the November 13 addendum. Classwork has display priority and both assignments remain available. The earlier suggestion that individual work should be preferred is superseded. Implementation details labeled proposed remain reviewable. Teacher-directed focus is a new workflow distinct from existing published pathway requirements, pacing targets and frozen diagnostic assignments.

## CSG-TDL-01 — Author and deliver a learning focus

**Roles:** owning teacher and enrolled students. From a class, choose **Assign learning focus**, recipient scope (one student, selected students, or whole class), target (area, skill, defined skill group, or supported course activity), immediate/scheduled start, and advisory/restricted mode. Advisory is the default. Restriction requires the teacher to select **Restrict navigation** intentionally and preview who and what will be affected. Reason and release condition are optional. Teachers can view status, edit, reassign, release restriction and end assignment. Reassignment issues a new focus or explicit revision with traceable lineage. It preserves evidence and existing restrictions unless the teacher explicitly ends or releases them.

**States/data:** draft, scheduled, active, ended, and canceled before start. Per-recipient status distinguishes available, started, in progress and complete, plus independent restriction status and evidence availability. Store stable assignment/class/recipient references, versioned target references, scope, start time and time zone, optional purpose/reason/completion policy, restriction grant state and audit history. Use owner-authorized actions and server time for scheduled activation. **Dependencies:** CSG-CUR-01/02, CSG-SEC-01/03. **Accessibility:** labeled scope and target selectors, accessible recipient multi-select and preview, keyboard review and clear result after publish. **Acceptance:** CSG-AT-TDL-09 and 11. The same teacher can issue each recipient/target combination supported by the course. A scheduled item does not guide or restrict before activation. Replaying a save cannot create duplicate assignments or grants.

**Approved defaults · CSG-DEC-12.** Whole-class assignments follow current active membership, including students who enroll after activation. An assignment to selected students uses the recipient snapshot saved with that assignment; eligibility still requires current enrollment. Record applicability over time for reporting. Use mapped, observable task evidence for completion where supported and authorized teacher confirmation otherwise. Publish the criterion with the work. Completion is separate from proficiency, and one attempt keeps one evidence identity even if it meets more than one explicitly configured assignment criterion. Target versioning, attribution rules for same-target work, and historical reporting storage are implementation details.

## CSG-TDL-02 — Classwork priority, switching, and resume

**Roles:** enrolled students and teachers. When class-wide and individually assigned work overlap, show **Today's Classwork** first, regardless of creation time. Show **Your Catch-Up Work** below it. Each item identifies its origin. A student may start or switch to either without completing the other. The teacher can direct the order verbally. A shared target receives one recommendation with both source labels and a way to view each assignment's status. Keep all actual assignments and restriction records distinct. Selected-group work appears with catch-up by default and identifies its group origin. Within a section, the proposed order is teacher-set order then start time.

On open or return, show the available focus prominently, with **Start Assignment** or **Resume Assignment**. A new assignment never auto-navigates an active task or discards in-progress input. Surface the notice at a safe task boundary. Explicit switching preserves each assignment's supported attempt/position state. Capture the original independent pathway position before entering assigned work and keep it separate from per-assignment position. On completion show **Resume Previous Path** and **Continue From Here** when meaningful and permitted. If an active restriction covers the previous path, retain that position and explain when resume is available. Completing an assignment does not silently clear a restriction.

**States/data:** new, active, resumed, paused, complete, unavailable and restricted previous path. Persist assignment progress by recipient/assignment, and independent position separately by learner and course. Use existing activity resume support or an approved checkpoint adapter, with no claim of durable in-question resume until verified. Never force a switch that loses an in-progress answer. **Dependencies:** CSG-STU-03/04, CSG-TDL-04, CSG-MAS-04. **Accessibility:** distinguish origins and status in text; announce new work without stealing focus or interrupting input. **Acceptance:** [CSG-AT-TDL-01 through 03](acceptance-tests.md#teacher-directed-learning).

## CSG-TDL-03 — Restriction visibility, edit, and release

**Roles:** owning teacher and affected enrolled students. **Active Restrictions** is at the top of the class dashboard. Show unique affected-student count, student IDs, assigned target, whole-class or individual scope, effective access and the assignment or assignments that create it. Distinguish selected-group origin when present. Default roster order lists restricted students first with text badges, filters and sorting. A restriction defaults to manual release even if assignment completion is recorded. Any automatic release is optional and intentionally configured by the teacher. Offer quick release by student and grant and bulk release, with a preview of what remains active.

**States/data:** inactive, scheduled, active, released, ended by its parent assignment. Track teacher actor, timestamp, scope/target revision, previous/new state, optional reason and release mechanism. Bulk operations show each success or conflict, preserve independent grants, and permit safe retry. If a whole-class grant is released for one student, the release affects only that student and that grant. A recorded grant-specific exemption is the proposed mechanism. **Dependencies:** CSG-TCH-02, CSG-SEC-03, CSG-TDL-04. **Accessibility:** keyboard actions, labeled badges and accessible bulk confirmation/results. **Acceptance:** [CSG-AT-TDL-04, 05, 08 and 12](acceptance-tests.md#teacher-directed-learning).

## CSG-TDL-04 — Effective access and overlap

**Roles:** enrolled student and owning teacher. Apply class membership, published target availability, role authorization and ordinary course boundaries first. Evaluate only active assignments and applicable unreleased restrictions for the learner. When any applicable restriction is active, permit every eligible destination from the student's active assigned work, including advisory classwork or catch-up, and the authorized scope of their active restriction grants. Apply the **union** of those destinations. Never intersect class and individual scopes or replace one restriction with another. Classwork display order grants no scoring, completion-order or permission override. When zero restrictions apply, ordinary exploration applies.

| Applicable state | Expected effective access |
| --- | --- |
| Class and individual assignments, both advisory | Both assignments and ordinary exploration |
| Individual restricted A, class advisory B | A and B available; unrelated practice may be blocked |
| Class restricted B, individual advisory A | A and B available; unrelated practice may be blocked |
| Class restricted B and individual restricted A | A and B available; both grants visible. Release of one leaves the other active. An active assignment whose restriction was released is still an assigned destination. |
| End A while B remains restricted | A's own grant and active assignment cease to apply. A stays available only if otherwise authorized by B or another active assignment. B's grant remains. |
| Release last applicable grant | Ordinary exploration restored. Active assignments stay listed and retain progress. |
| Completion under manual release | Grant remains active until release or explicit end of its parent assignment. |

**Approved enforcement boundary · CSG-DEC-10.** Apply the same decision to Map, List, search, direct class links, return links and class-launched activities. An unrelated class launch is blocked when an applicable grant requires it, even if an old link or client state still shows it. Keep access to reports, accounts, accessibility support and allowed assignments. The server verifies class authorization for protected launches and for evidence and assignment writes. Public guest games remain independently accessible even on the same device. A guest route cannot authorize a class launch, and its attempts cannot fulfill class assignments or be silently attributed to a class. Keep any explicit switch to independent practice clearly labeled.

**Offline or unknown permission:** keep the last known context clearly labeled and preserve in-progress input. Defer a new class launch when permission is stale or unknown until verified. If eligibility changes mid-question, preserve input, explain the change at a safe boundary and revalidate on the next launch. A queued class result remains pending until the service can validate its original class context and authorization; reject invalid replay without turning it into a guest result. Never imply that a locally saved response earned synced credit.

**Proposed mechanism:** one shared class-scoped eligibility contract and server-verifiable launch context. Normalize area, skill, group and activity targets to the same eligible destinations. Specify permission freshness, replay and active-attempt validation during implementation. Static public games require explicit separation of guest access and protected class state.

**States/data:** allowed, blocked, pending transition, released, stale or unknown, offline and unauthorized. Store grants and release history independently. Never leak cross-class membership or assignment metadata. **Dependencies:** CSG-NAV-02/03, CSG-SEC-01/03, CSG-TDL-01/02/03. **Accessibility:** a blocked launch states why and offers an allowed destination. **Acceptance:** [CSG-AT-TDL-04, 05, 08 and 10](acceptance-tests.md#teacher-directed-learning), plus CSG-AT-09. Use the existing evaluator and official assessment process under CSG-MAS-04.
