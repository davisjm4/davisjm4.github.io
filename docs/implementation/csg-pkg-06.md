## Implemented and tested

The shared pathway module normalizes published areas, skills, skill groups and activities to skill-and-activity destinations. It applies classwide work dynamically to active members, uses the stored membership snapshot for groups and individual work, and gives class work priority in the result. Recommendation grouping preserves each assignment reference and recipient lists stay out of the student result. Effective class access uses the union of all currently available assigned work when any applicable restriction is active. Completion leaves a manual grant active. Release is per grant and profile. Access to a newly added skill requires an explicit target revision, even if the area originally covered by the assignment still exists.

Run `node --test cs-games/pathway/tests/assignment-access.test.mjs`. Four deterministic tests cover the policy portions of CSG-AT-TDL-01/04/05/09/12, including both creation orders, overlapping advisory/restricted work, same-game isolation, release of one grant, scheduled activation, new class members, revoked membership and stale permission. An additive storage draft separates immutable assignment revisions, selected recipients, releases and completion status from practice and official assessments. A disposable SQLite check applies it twice, rejects duplicate request IDs and changes to stored revisions, checks evidence preservation, and verifies class deletion cascades. Run `node --test cs-games/pathway/tests/learning-focus-storage.test.mjs`. The migration has only run against synthetic local data. The draft Worker previews a proposed assignment under existing owner authorization. It resolves the published class target, validates a scheduled class time zone and active recipient scope, defaults to advisory, and performs no storage writes. Run `node --test cs-games/pathway/tests/learning-focus-preview.test.mjs`. It covers all target and recipient types, rejected other owners and student credentials, cross-class and revoked profiles, and unchanged practice records. A separate publish route is disabled by default. In the synthetic fixture it requires the reviewed assignment, teacher, pathway revision and active recipient set. The immutable revision and selected recipients are written atomically. Concurrent identical retries return one record. The tests reject tampering, stale previews, changed active membership, and a revoked recipient. Keep publishing disabled until the protected launch and evidence paths are wired and verified.
