# Java Games instructional quality update

Scope: Variable Lab, Debugger Lab, Loop Lab, and the requested additional audit of the only other implemented Java game, Array Lab. No CSP source, branding, routes, collection-editor code, session tracker, or Session Summary logic changes. Deployment is through the existing GitHub Pages repository.

## Changes and instructional review

| Generator | Findings and changes | Representative examples reviewed |
|---|---|---|
| Variable Lab | Assembly purposes, names, types, and values now come from matched scenarios. Prompts show purpose and actual value, without naming the type or identifier. Value replaces Literal. One identifier matches each purpose; other names refer to different data. Optional introductory convention explains the intended most appropriate type, acknowledging legal widening. Identification has relevant alternate declarations in shuffled order. Conversion classification varies widening, explicit narrowing, and no conversion. | All 12 assembly purpose/type combinations, integer vs decimal health, ticket prices, usernames, Boolean availability, initials, and all three conversion classes. |
| Debugger Lab | Lexical token buttons and a gap only at a missing component replace whole-line selection and every-line insertion controls. Neutral task/context, realistic repair alternatives, no selection-only correctness. Tokens use native focusable buttons, 44px vertical touch targets, visible selection, preserved whitespace and code-panel horizontal scrolling. Compiler messages are optional and captured from the exact source with javac 17. | Every retained template (42), including constructor/method semicolons, earlier brace errors producing later diagnostics, overloaded remove, scope, numeric conversions, integer arithmetic, overflow, String contents, and array bounds. |
| Loop Lab | Initialization prompts ask about the control variable; relevant score/bonus declarations vary their order. Accumulator and counter updates must be distinguished. Body selections include all body statements. Any displayed reference to the control variable is accepted for its identification. No scope giveaway in post-loop prompts; such questions only use accessible counters. Distractors model endpoints, missed/final updates, and count mistakes. A Java-only hidden-control CSS rule prevents button layout styles from exposing Watch Execution early; its handler also refuses pre-submission execution. Execution stays hidden before a complete submission/reveal; watching an active challenge requires intentional reveal confirmation. | All 17 mode/concept combinations, decreasing/increasing steps, exclusive/inclusive bounds, last vs after values, printed sequences, rectangular/triangular nested loops, and declaration order. |
| Array Lab | Invalid indices vary negative and upper-bound errors; correct choices no longer always have the largest numeric value. Search distractors are actual possible indices or -1. Count distractors remain valid count quantities. Sum/element distractors reflect partial totals, duplicate first elements, neighboring positions, and confusing index with value. Extremum questions ask for the accumulator value rather than announcing the algorithm. Collection interaction remains unchanged. | All 24 concepts, numeric/String ArrayLists, fixed arrays, duplicate values, ordered operations, first-match search, extrema, visited positions, and 2D rows. |

The ambiguous dangling-else template (`nested-if-else`) was removed: repairing its structure required relocating/bracketing a block rather than one token or relevant gap. Its former bank also lacked meaningful alternatives. Selection/logic practice remains in other templates. The enhanced-for-copy example was revised to allow an actual identifier repair to a stored array element. The constructor-name example now initializes a field, so declaring a similarly named void method does not satisfy the goal through an implicit default constructor. Equivalent valid closing/opening brace removals are accepted and compiled individually.

## Automated verification

- General engine regression: 7,800 seeded challenges (600 per game mode), plus exhaustive bounded loop mathematics, unique metadata, correct/wrong validation, and Java/CSP storage isolation.
- Variable quality: 500 assembled declarations compiled by javac, all 12 purpose/type combinations, leakage and name checks, incorrect pieces rejected; 100 identification samples and 300 conversion/structure samples; default mixed practice checked.
- Debugger quality: 500 randomized challenges covering all 42 templates, specific lexical selections, complete two-part scoring, neutral prompts, plausible banks, and 24 equivalent brace repairs compiled.
- Debugger repair behavior: all 126 candidate repair programs compiled or their compiler failure observed. Every model repair executes its intended behavior. The 37 compiling distractors are disproved by actual JVM results, including unequal equal-length String counterexamples. Nonterminating alternatives are bounded by a process timeout/output cap in development tests only.
- Loop quality: 1,000 randomized challenges, independently interpreting the displayed conditions and steps to verify termination, count, endpoints, printed sequences, nested pairs, accumulator trace, scope, and shuffled declarations. Another 100 full programs compile and match the animated output under the real JVM.
- Array quality: 1,200 randomized challenges, independently interpreting collection operations and checking indices, sums/counts/search/extrema, unique valid choices and varied answer positions.
- DOM interaction regression: 4,571 assertions covering all modes, wrong/retry/reveal scoring, token selection without premature feedback, incomplete submissions, collection operations, Watch Execution gating and reveal cancellation, navigation/defaults, persisted sessions, and report identity/print/reset/cancel behavior.
- Compiler regression (`compiler-tests.mjs`): 732 template/generated-source checks, followed by 63 additional compiled behavioral samples matched to real JVM output. All runtime-defect templates throw for the displayed input; all model repairs run. Diagnostics regenerated against the exact displayed programs, for values 2–9.

Tests use development-only Node/linkedom and local OpenJDK 17. Student pages execute no Java compiler and load no new runtime dependency or external service.

## Limitations

DOM tests verify event/state behavior, not physical Chromebook or smartphone touch performance. Native buttons support browser keyboard activation, and CSS preserves code scrolling; rendered-device QA must be distinguished from DOM simulation. The local Chromium download failed, but the cloud Chrome browser was available for desktop rendering and interaction checks on the deployed pages. Live checks verified declaration assembly, keyboard repair selection, wrong-answer hints, independent retries, reveal locks, and correct cross-game report totals. A rendered CSS check found shared button styling overriding the hidden attribute; the Java-only override and a handler guard correct that issue. Physical-device and mobile-viewport testing remain unverified. Student reports remain browser-local formative evidence. This update does not change their storage schema, accuracy formula, reset confirmation, or privacy behavior.
