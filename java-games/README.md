# Java Games

Static Java-reading practice at https://davisjm4.github.io/java-games/, in the existing Pages repository. HTML/CSS/native JavaScript only. No code editor, arbitrary compilation, FRQ Builder, backend, accounts, student-data uploads, telemetry, or paid services.

## Initial games

- Variable Lab: int/double/boolean/char/String; clickable annotated components; declaration/initialization/assignment; literal/value; widening and narrowing conversions; reassignment; guided declaration pieces. Mixed default. Assemble balances the five types with a shuffled queue and draws scenarios from 21 context families in `variable-scenarios.js`.
- Debugger Lab: select a faulty lexical token or the relevant missing-component gap AND a correction, then check both together. Verified templates cover syntax, runtime, logic, and tricky earlier-source faults. Compiler diagnostics are captured from OpenJDK 17, not invented. The production site uses known templates, not a compiler.
- Loop Lab: for/while structural regions, start/update/last-used/count/after-update questions with scope enforced; increasing/decreasing steps; <, <=, >, >=, !=; nested rectangles and row-dependent grids. Optional stepped/animated execution shows initialization/conditions/body/updates. Watching after an incorrect attempt intentionally reveals the challenge and prevents independent credit; cancellation leaves it active.
- Array Lab: visual starting collections; drag/touch/keyboard working copies, reusable bank values, duplicates, insertion gaps, removal zone, reordering, replacement, undo/reset. Dynamic ArrayLists have no fixed final slots. Arrays keep fixed length. Includes zero-based indices, length/size, visited elements, sums/counts/min/max/search, numeric and String ArrayLists, array/ArrayList traversals, and 2D row-update grids.

## Robot Algorithms

Public route: `/java-games/robot-algorithms/`. A standalone page (its own `script.js`, `engine.js`, and `style.css`) registered on the hub like Math Lab (`robotGame` from `robot-algorithms/engine.js`). Students predict, build, and debug short legal Java programs that steer a robot on a grid: Predict the Robot, Loop Navigator, Build the Route, Conditional Robot, Debug the Robot, and Methods and Reuse (Mixed Practice default). "Where does it finish / which way does it face" questions are answered on the grid itself: click a cell to move the robot there and click the robot to turn it right (directions are Up, Right, Down, Left). Counting, outcome, and debugging questions use four choices. Loop Navigator and Methods and Reuse include if statements inside loops and methods. A deterministic interpreter (no eval) runs the supported subset (robot.move/turnLeft/turnRight/canMove/atGoal, for, while, if/else, &&, ||, !, int variables with + - * / %, void methods with int parameters) with a 2,000-step limit. Every answer is computed by simulation, wrong answers are matched to simulated misconceptions, and each debug option is run so exactly one fix works. Results use the shared `javaGames.session.v1` tracker with one topic per mode: an incorrect first answer is revealed immediately (attempted + incorrect + revealed); Build the Route records its first run, and later successful runs count as Solved after retry. Tests: `npm run test:robot`; optional `npm run test:robot-jvm` compiles generated programs with javac and compares JVM results with the interpreter.


CSP List Lab reuses the collection editor with explicit one-based indexing. Its code-building mode is preserved. Java always uses zero-based indexing.

## Method & Constructor Lab

Public route: `/java-games/method-constructor-lab/`. A standalone page (`script.js`, `engine.js`, `style.css`) registered on the hub like Math Lab and Robot Algorithms (`methodLabGame` from `method-constructor-lab/engine.js`). Nine modes, Mixed Practice by default: Identify Method Parts and Identify Constructor Parts (tap real code tokens; tap again to expand to a whole parameter, statement, or body), Match Calls to Signatures (argument types/order/count, int-to-double widening, overload resolution), Organize Arguments (tap-to-order, including same-type parameters and decoys), Return Types & Return Statements (completing returns, boolean requirements, void and `return;`, every-path returns), Constructors & Object Creation (`new`, overloaded constructors, no implicit default constructor, constructor vs. method), Method Calls & Returned Values, Fix the Method or Constructor, and Access Modifiers (public vs. private, private members used inside their own class, private constructors). Overload choice uses the JLS most-specific rule with widening (no boxing/varargs needed). One scored submission per challenge in the shared `javaGames.session.v1` tracker (topic per mode; wrong answers are revealed immediately). Tests: `npm run test:mcl`; optional `npm run test:mcl-jvm` compiles every generated program and every choice with javac (valid choices must compile, invalid ones must fail) and runs returned-value and overload programs on the JVM.

## ArrayList Lab

Public route: `/java-games/arraylist-lab/`. A standalone page (`index.html`, `script.js`, `engine.js`, `style.css`) registered on the hub like Method & Constructor Lab (`arrayListGame` from `arraylist-lab/engine.js`). Five modes plus Mixed Practice (default): Access & Update, Insert & Remove, Search & Size, Traverse & Trace, and Arrays vs. ArrayLists. Twelve challenge families (53 templates): declaration/wrapper types, get vs. set, choosing the operation, add to the end, insert at an index, remove by index, remove by value vs. index (remove(int) vs. remove(Object) overloads), size and valid indices, contains/indexOf, traversal, removal during traversal (skipped elements, backward and i-- loops), and arrays vs. ArrayLists (length vs. size(), [] vs. get/set, fixed vs. dynamic, autoboxing). Students tap a list element, tap an insertion gap, tap every element a loop removes, or choose one answer; index labels stay hidden whenever an index is the target. After one scored submission the page shows the correct answer, an explanation, a misconception note for the chosen distractor, a before/after list with inserted/removed/replaced/shifted elements, and an optional step trace. Every answer is computed by a model of java.util.ArrayList; distractors come from simulated misconceptions. Results use the shared `javaGames.session.v1` tracker with one topic per mode (a wrong first answer is revealed immediately, like Method & Constructor Lab). Tests: `npm run test:arraylist`; optional `npm run test:arraylist-jvm` compiles and runs every template's Java with javac/JVM; optional `python3 ../tests/arraylist-lab-browser.py` drives Chromium at Chromebook and phone sizes.


## Sessions and privacy

Java uses localStorage key `javaGames.session.v1`; CSP uses `cspGames.session.v1`. They do not share performance or optional student identity. Each has its own printable Session Summary and confirmed Cancel/Reset dialog. Retries retain one challenge ID. First-try accuracy uses submitted challenges; revealed answers never earn independent credit. Optional name/period and results stay in the browser. Clearing data/private browsing can remove them; reports are formative evidence and are not tamper-proof. Active practice time accumulates only while a visible practice page is engaged; inactive, hidden, and away time are excluded.

## Tests

`npm install` and `npm test` in this folder. linkedom is a test-only dependency. Compiler checks use `compiler-tests.mjs` with OpenJDK 17 and a local batch harness (`compiler-harness.java`); no compiler/server is loaded by students. Generator tests cover seeded challenges, exact loop mathematics, metadata uniqueness, and separate session stores. DOM tests exercise every mode, both parts of debugging, wrong-then-right retries, reveal locks, collection operations, walkthrough reveal/cancel, session persistence, and summary reset/print actions. CSP regressions run separately; the shared collection test checks mouse drag/drop, touch-pointer, tap/keyboard controls, duplicates, growth, undo, reset, and both index bases.

DOM simulation does not verify physical Chromebook/mobile touch behavior, rendered CSS, or printed/PDF layout. Manual visual QA remains recommended before assignment.

The current quality-update checks and instructional review are documented in `QUALITY_AUDIT.md`.
