## How configurations are counted

A **reasoning configuration** is the reasoning signature defined in `compose/signature.js`: the canonical program (every class, field, method, parameter and variable renamed by first occurrence; literal values replaced by their type), plus the branch outcomes taken during execution, any exception, the pattern of equal constructor arguments, and the canonical query. Renaming, switching domain (Player → Tank), changing literals without changing any decision, rewording, and answer order therefore do **not** create a new configuration. For "how many objects are created" questions, the operations are counted as an unordered multiset, because their order cannot change the count.

The counts below are **observed lower bounds**: the number of distinct configurations seen in 1,000 seeded challenges per cell. The true pool is at least this large.

**14- and 20-question sessions:** zero reasoning-configuration repeats in every cell and seed (asserted). Sessions never switch mode or difficulty to avoid repetition (asserted). Once a cell's pool is exhausted, the session reuses the least recently used configuration with new details, and the UI labels that question **Review**. Small Beginner pools reach this point between roughly 40 and 100 questions; most Intermediate and Advanced cells did not repeat a configuration even in 500 questions. Exact repeats were 0 in every 500-question session.

Normalised-program and object-graph repeats are expected to be higher than reasoning repeats: two questions can share a program skeleton or final object graph while differing in decisions taken, the target of the question, or the equal-argument pattern. Those counts are reported, not used as the target.
