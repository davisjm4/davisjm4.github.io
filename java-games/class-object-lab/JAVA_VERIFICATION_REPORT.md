## Harness

Each challenge's displayed program is emitted by the same emitter as a complete `Main.java`: the classes become top-level classes, the helper methods become static methods of `Main`, and the main statements are placed verbatim in `run()`. Every program gets its own package, one `javac` call compiles each batch of up to 300 programs, and one JVM runs them through a generated `Runner`. Harness-only additions, which are not part of the displayed code and do not change its semantics:

- A reflection dump after the last statement prints every main variable, every reachable object (identified by first-encounter order through an `IdentityHashMap`, never by identity hash codes), all of its instance fields, and all static fields. The simulator prints the same format, and the two must match exactly.
- For object-count questions, a harness-only instance initializer `{ Main.__allocs++; }` counts constructions, including objects created inside methods and temporary objects.
- Compile-error alternatives are compiled separately with `-XDrawDiagnostics -XDshould-stop.ifError=FLOW`. Without the second flag, javac skips its definite-assignment (flow) phase once any file in the batch has an attribution error, which hid uninitialised-local errors in an early run. Each must fail with the expected diagnostic key (`report.access`, `non-static.cant.be.ref`, `var.might.not.have.been.initialized`, `cant.resolve.location*`, `cant.apply.symbol`).

## Mismatches and corrections during development

The JVM runs found these defects in the generator or the harness; each was fixed and the full run repeated:

1. Reverse-reference questions lost their hidden "original reference" statement when serialised, so the check could not be compiled. The serialiser now includes `pre`.
2. Getters access check: the extra public field could be named `level`, colliding with the `Tank` domain's field (a duplicate declaration). Names now avoid every domain field, and a structural validator (`compose/validate.js`) rejects duplicate fields, methods, constructors, parameters and locals before any program becomes a challenge.
3. Parameters family: two returning helpers could declare the same result variable twice. Fresh names are now allocated, and the validator also guards this.
4. Reverse reference: a wrong alternative declared `d`, which can be an existing variable in the `Counter` domain. Fixed, and every selection fragment is now validated as well.
5. `Car.speed` (a private instance field) was labelled a static-context error; javac reports private access first. The compile reason now matches javac.
6. Harness: raw diagnostics print bare file names (so each file now has a unique name), the diagnostic-key regex did not allow hyphens, and javac's flow phase was being skipped (see Harness).
The simulator itself caught one generator defect before the JVM ran: a static-family call to `add` instead of the domain's method name.

## Supported Java subset

Classes with `int`, `double`, `boolean`, `char`, `String` and class-typed fields; instance and static fields with initializers; overloaded constructors and `this(...)` chaining; instance and static methods; `this`, `return this`, shadowing parameters and locals; `if`/`else`, the ternary operator, `Math.min`/`max`/`abs`; compound assignment and `++`/`--`; String concatenation with `String.valueOf` rules; `toString` overrides; `==`/`!=` on references and primitives; `null` and `NullPointerException`; static helper methods in `Main` taking and returning references.

**Not supported (never generated):** inheritance, interfaces, `equals`/`hashCode` overrides (so `==` questions never involve `equals`), arrays and collections, loops, exceptions other than `NullPointerException`, `final`, nested or inner classes, generics. Default `Object.toString` output is never presented as a predictable value; the JVM test checks it against the pattern `ClassName@hex`.
