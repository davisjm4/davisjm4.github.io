# AP CSP coverage audit

35 topics and six practices. Every topic has at least introductory practice, but no topic is claimed comprehensively covered. Classifications describe the listed modes, not every objective or essential-knowledge item. No topic is marked Reinforced: unrestricted explanation and authentic project work remain teacher-reviewed.

Source: [Effective Fall 2023, current official AP Central CED retrieved 2026-10-13](https://apcentral.collegeboard.org/media/pdf/ap-computer-science-principles-course-and-exam-description.pdf). LO/EK identifiers reference the official source; descriptions are paraphrased. PDF page numbers count PDF pages.

Classification: Not covered = no meaningful practice; Introduced = identification; Practiced = randomized application; Reinforced = varied application, analysis, and independent explanation.

## Six computational thinking practices

### 1. Computational Solution Design

Partial: routing/scheduling and Algorithm Architect construct solutions within stated constraints.

Open-ended design, user research, full projects, and collaboration still require authentic assessment.

### 2. Algorithms and Program Development

Practiced within templates: executable constructions, list transformations, equivalent configurations, edge-case tests.

General program development, large algorithms, and broader alternative implementations remain partial.

### 3. Abstraction in Program Development

Practiced within templates: list/procedure identification, parameterized constructions, structured complexity explanations.

Choose and implement abstractions for original projects; defend them in independent writing.

### 4. Code Analysis

Practiced within templates: boundary/branch/list/error cases, expected vs actual, Boolean and search analysis.

Full debugging strategies, arbitrary code, and open-ended testing explanations remain partial.

### 5. Computing Innovations

Practiced in bounded evidence scenarios: impacts, privacy, bias, access, crowdsourcing, trade-offs.

Authentic innovation research, diverse stakeholder effects, and extended argumentation remain essential.

### 6. Responsible Computing

Introduced/practiced in scenarios: consent, attribution/license rules, accessibility, password/reuse/MFA/phishing.

Authentic collaboration, attribution of original projects, and responsible real-world data handling cannot be certified by browser selections.

## Authentic work and reporting limits

Collaboration, original project design, user research, documentation, attribution, and Create written-response preparation require teacher-reviewed projects and writing. Structured games can scaffold those skills but cannot certify their authentic completion. Session Summary is local formative evidence, not a tamper-proof assessment. Teacher Tools / Canvas QTI Export remains deferred.
