Create requirements and vocabulary

These short practice examples focus on specific components. They are not complete Create submissions and do not guarantee a score.

The full program includes input, output, a list or other collection that manages complexity, a student-developed procedure with parameter(s), calls, and an algorithm with sequencing, selection, and iteration in the selected procedure. PPR procedure evidence shows a parameter affecting functionality and the procedure call. PPR list evidence shows storage and use of the same list to manage complexity. Input and output are not separate PPR boxes.

Selection is choosing instructions based on a condition. An IF statement is one implementation. Control structures also include sequencing and iteration; the term does not mean only IF. Iteration means repeated execution. A loop need not have a separate counter.

A parameter is declared in a definition; an argument is supplied at a call. RETURN sends a value back to the caller and does not necessarily display output. Input can include user events, devices, streams, or files. Output can include text, sound, touch, visuals, or movement. A return value is optional when the procedure’s task does not need one.

Questions use instructional paraphrases of AP terminology, not reproduced exam questions. WHEN StartPressed is explicitly defined event notation for those examples; it is not an AP reference-sheet instruction.
