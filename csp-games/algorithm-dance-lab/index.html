    Live performance
    Build your response with the same blocks in Create, then play it here. Read the Note, Beat or Event inputs in your program to decide what the robot does.
    Stopped · Start Live, then use the keys below.
    Computer keys A S D F G H J K · touch the same pads on a phone. Input Event is note, release or beat; Beat starts at 1. One response runs at a time; only the newest waiting input is kept.
    How to program a response
    In Create → Controls, choose Use in program beside Note, Beat or Event. Build IF conditions using those values, then call your own procedures. In Live, choose which event runs your main routine. The main routine executes afresh for each input; variables do not persist between events. Lists and procedures remain part of your program.
    For a melody or local recording, choose its music source and enable sound before Start Live. The selected BPM supplies the beat clock; Tap tempo helps align a recording. Automatic beat detection is not included.
    Your controls
    Set a value, then choose Use in program to add its input block. Use that value in repeats, decisions or procedure calls. Configure lets you rename a control and change its choices.

    Movement, language and music guide
    touch uses both hands for head, shoulders, knees or toes. Stomps plant one foot; slides translate in the robot’s current left/right directions; criss-cross crosses and reopens the feet; cha-cha is a four-beat side sequence; Charlie Brown is a four-beat forward/back rock. These are consistent stylized equivalents, not motion-capture reproductions.
    Parameters belong to definitions; arguments are values passed by a call. IF needs a Boolean value. Lists start at index 1; use LENGTH and FOR EACH to process them. List values are references. A procedure has local scalar bindings; it can read main-track variables. Do not mutate a list while traversing it. Parallel tracks have their own variables; shared input lists are read-only across tracks.
    Audio, moves and rests occupy beats. Definitions and control flow take no beats, but appear in the debug trace. Reduced motion changes poses, not timing. Runtime limits: 400 blocks, 800 emitted events, 6,000 work units, call depth 16, nesting 12 and five-minute performances. No arbitrary code evaluation.
