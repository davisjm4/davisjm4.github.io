Learn / Help — range and precision

Computers encode numbers with bits. With a limited number of bits, only a limited set of values is available. A mathematically valid calculation can produce a value the destination cannot represent.

Overflow: not enough range. Unsigned n-bit whole numbers range from 0 through 2ⁿ − 1. Four unsigned bits hold 0 through 15: a result of 16 is outside the range. In n-bit two's-complement signed integers, the minimum is −2ⁿ⁻¹ and the maximum is 2ⁿ⁻¹ − 1. Four signed bits hold −8 through 7; −9 is also outside that range. This is integer range overflow below the minimum, not floating-point underflow.

Overflow does not universally mean wrapping to zero. A system might wrap, report an error, saturate, or follow another rule. This lab does not assume a stored result without a stated policy.

Roundoff: not enough precision. A decimal format storing two decimal places saves 3.14159 as 3.14. The value fits the range but must be approximated. Repeating fractions such as 1/3 cannot be stored exactly in a finite decimal expansion.

Binary fractions can be exact: 0.5 = 1/2. A finite binary fraction cannot represent 0.1 exactly, even though a suitable decimal format can. The base and available digits both matter. Floating-point formats keep a limited number of significant digits; their spacing changes with magnitude, rather than always rounding to a fixed number of decimal places. Teaching floating-point models here explicitly state their base and precision; they are not claims about every actual machine.

Neither: fits and is exact. An unsigned 8-bit integer can store 200 exactly. A decimal format with two decimal places can store 3.25 exactly. A decimal point does not automatically imply an error.

Deliberately converting 3.9 to 3 with an explicit truncation instruction is different from the nearest-value precision model used here. This lab does not classify unspecified conversions or floating-point values too tiny in magnitude.
