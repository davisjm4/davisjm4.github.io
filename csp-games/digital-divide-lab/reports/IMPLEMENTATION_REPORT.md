## Implementation

Five free modes: Identify the Barrier, Predict the Impact, Choose the Best Solution, Evaluate the Tradeoff and Interpret the Evidence. Separate five-topic filter; Mixed defaults. One scenario, four native choices, one terminal scored selection, then key/rationale/alternative feedback. No essays, typing, drag/drop or level locks. Next, help and filters do not count as attempts. Learn is closed initially and provides distinctions and worked examples.

content.js contains64 text frames ×5 operational clues. data.js contains16 evidence families ×5 numeric/operating conditions. model.js holds stable modes, barriers, contexts and intervention metadata; engine.js provides one400-instance representation, validation, seeded finite selection and feedback. data-view.js displays supplied facts only: scoped table headers, fictional caption, neutral responsive HTML percentage bars, ARIA description and text equivalent. Chart labels remain regular readable text on narrow layouts. No answer annotation is added before submission.

The shared tracker is the only score source. Disjoint cumulative topic/barrier and actual-mode/selected-filter buckets remain accurate beyond the256-record log limit. Summary renders game, topic/concept, practice-mode/filter and Big Idea5 totals. Metadata includes stable question/family, primary/supporting objective, mode, barrier, context and intervention categories. A future readiness pathway is prepared, not built. Shared active time excludes hidden/idle time under existing conventions. Optional repeat history is tied to the daily session ID; damaged history cannot block practice. No accounts, backend, uploads or runtime external APIs/assets.

Both launch catalogs, legacy activity listing and catalog-render tests are integrated; legacy hub count28. Existing impact, AI, vocabulary, networking and other games remain intact. New CI workflow uses the established dependency/test configuration.

## Instructional validation

80 authored instructional families /400 finite compositions;20 contexts,12 barriers,12 intervention categories. Distinguish recurring price from coverage, availability from task suitability, capacity from continuity, task skills from language/interface needs, access from meaningful use and offered programs from measured outcomes. Cases establish actual constraints rather than infer them from demographic traits. Barrier dimensions can overlap; scoped prompts and alternatives identify the supported distinction.

Solutions explicitly establish goals, deadlines, compatibility, coverage, costs or authorized support assumptions. No intervention is treated as universal. All data are visibly fictional. Counts/proportions, percentage points, matched cohorts, subscription/coverage, paired requirements, task demonstrations, survey coverage and causation limits are reviewed. Numerical direction reverses in several variants. Source, scope and per-family author rationales are in CONTENT_REVIEW.md and review-fixtures.js. External educator review is pending; structural tests are not certification of semantic truth.
