    Learn / Help — roles working together

    The Internet connects independently operated networks using shared protocols. A protocol defines communication rules. A network is a connected set of devices; the Internet is a network of networks, and the Web is one application system using it.

    Data can travel as packets: pieces with delivery metadata. Shared links can carry packets from many exchanges. Packets can take different routes, arrive out of order, be delayed or be lost. Packet switching does not itself guarantee ordered arrival.

    A simplified TCP/IP-style model

    This four-role model is useful for reasoning. Other networking references organize layers differently; you do not need seven OSI layers for this lab.

    Protocol-role reference

    • DNS resolves names to records such as IP addresses. It is an application service, not a compulsory forwarding layer traversed by every packet. Valid cached records can avoid a new lookup.
    • IP supports addressing and forwarding across networks. It does not guarantee a complete ordered application stream.
    • Routers use forwarding information to choose next hops. A conventional layer-2 switch forwards local-LAN frames using link-layer information. Real devices can combine functions; scenarios state the role being assessed.
    • TCP supplies a reliable ordered byte stream between its endpoints under its operating assumptions, using mechanisms such as sequence information, acknowledgments and retransmission.
    • UDP supplies datagrams without its own TCP-style delivery and ordering guarantees. An application or protocol above it can add recovery.
    • HTTP defines application requests and responses. HTTPS uses HTTP with transport security, commonly TLS; it is not a routing protocol.
    • TLS supplies channel-security features. A claimed identity still needs the validation required by the stated trust policy.
    • HTTP/3 uses QUIC over UDP. QUIC adds secure transport features and reliable streams, so web communication is not universally TCP-based.
    • Ethernet and Wi-Fi are local-link technologies, not replacements for application, transport and Internet responsibilities.

    Bandwidth is carrying capacity per unit time. Latency is delay. Shared-link congestion can create queues and packet loss. Extra paths are redundancy; continued operation despite failures demonstrates fault tolerance. Available alternatives help, but do not guarantee zero loss, zero delay or survival of every failure.

    One qualified web example

    For a new HTTPS exchange explicitly using HTTP/1.1 over TCP, with no usable cached address or existing connection: resolve the name, establish the TCP connection, establish and validate the TLS channel, then exchange HTTP requests and responses. This is an illustration of dependencies, not a universal wall-clock sequence. Cached results, existing connections and concurrent operations can change which steps are needed. A stated HTTP/3 exchange instead uses QUIC over UDP with integrated security.
