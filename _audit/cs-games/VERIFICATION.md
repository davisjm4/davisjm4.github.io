A Chromium scan opened 55 distinct activity routes from the catalog and supporting game links. Four initial activity views had multiple Session Summary controls.

| Affected production URL | Observed behavior on the local source snapshot |
| --- | --- |
| [String Lab](https://davisjm4.github.io/java-games/string-lab/) | **Session Summary** opens a lab-only modal and another **Session Summary** link opens the course report. The modal displays lab counters and offers **Copy summary data** and **Close**. The course report supports optional identity and print/PDF |
| [Create Performance Task Lab](https://davisjm4.github.io/csp-games/create-task-lab/) | Two links reach the same AP CSP report |
| [Trivial vs. Nontrivial Algorithms](https://davisjm4.github.io/csp-games/trivial-nontrivial/) | Three links reach the same AP CSP report |
| [Exam Readiness Pathway](https://davisjm4.github.io/csp-games/exam-readiness/) | Two links reach the same daily AP CSP report. The separate readiness dashboard shows longer-term evidence by design |

Workplace Readiness also has two entry controls after practice, **Performance** and **View session summary**. Both route to the same Performance screen. VEX Parts Sprint has one jump link to its inline Robotics summary, alongside the end-of-race results. These are distinct surfaces with their own roles.

### Reproduce and compare

1. In a fresh guest context, submit one answer in Loop Lab.
2. Open String Lab, submit one answer, and open the in-game **Session Summary** button. Its challenge count is one and it shows only String Lab practice.
3. Close the modal and open the shared **Session Summary** link. The [Advanced CS report](https://davisjm4.github.io/java-games/session-summary/) contains one String Lab attempt with the same first-try result and also contains the Loop Lab attempt. String Lab's existing bridge feeds the shared tracker from the same scored challenge event.
4. Reload String Lab. The modal resets to zero. The course report still shows the day's attempt. The duplicate surfaces can therefore disagree after reload and have different scope, labels, and time counters.
5. Enter a synthetic name in the course report and use **Print / Save as PDF**. The test confirmed the print button invoked the browser print function, the name appeared in the report, and Chromium generated a PDF. The [AP CSP report](https://davisjm4.github.io/csp-games/session-summary/) likewise exposed the name and print controls to a guest. Students can save the PDF and hand it in through their classroom workflow. The course report has no direct teacher-send control.

The full guest report remains reachable. The modal has displaced the name and print controls only for students who pick that entry point. The full report explicitly says identity and results stay in this browser. A synthetic name persisted after reload, and printing and changing the name produced zero write requests. The identity fields are hidden for signed-in profiles. This assignment leaves both report implementations intact.

If separately authorized, use the shared report as the only control titled **Session Summary**. Route the String Lab header action to that report. Keep mode, skill, and difficulty details as a clearly named lab breakdown if students use them. Collapse repeated CSP links where they serve the same navigation purpose. Keep name and period as transient print fields, preserve print/PDF, and test reload, guest isolation, and one shared attempt per scored answer before retiring the modal.

## Known limits

- The checks used Chromium viewport emulation, not physical devices, Firefox, Safari, or a screen reader. The browser audit suite drives real controls and the local Worker. Claude’s sandbox remains unverified.
- Google OAuth was exercised by the repository's token-validation test and live negative probes. A real teacher login and hosted D1 execution were outside the isolated walkthrough. Canvas quiz export is available locally; Canvas import and grade passback were outside this run.
- Formative levels follow the current rubrics and mappings. The fixture verifies automatically demonstrated Levels 2, 3, and 4 in Advanced CS. Teacher-reviewed levels in AP CSP, Robotics, and Workplace Readiness use the same official assessment form. Workplace Readiness practice reaches activity and skill reports. The existing app has limited concept-level pathway attribution for this course.
- The student UI provides demonstration guidance. Work is completed outside the application and reviewed by the teacher. There is no student-side portfolio upload in this workflow.
- Student practice and scores restore across browser contexts. Map position was verified on return from practice in the same context. A second context can reopen the skill and see synced evidence; the browser's exact map position is local.
